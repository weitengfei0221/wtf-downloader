## 1. 产品定义（一句话）

**一款界面现代、轻量、无广告的跨平台 HTTP/HTTPS 直链多分片下载器：把"大文件下载"这件小事做到快、稳、可恢复。**

- 快：多分片并行下载，充分利用带宽。
- 稳：断点续传、任务持久化、应用重启后无损恢复。
- 可恢复：暂停、限速、系统托盘常驻，下载进度永不丢失。

---

## 2. 问题陈述

**谁**：经常下载大文件（软件安装包、系统镜像、数据集、模型文件、视频素材）的 Windows 用户，后续扩展至 macOS 用户。

**什么场景下遇到什么痛点**：

1. 浏览器内置下载器是单连接的：大文件下载慢、断网/浏览器崩溃后进度全丢，只能从 0 重来。
2. 迅雷等国产下载器：广告弹窗、强制会员、限速、上传带宽偷跑，用户信任度持续走低。
3. IDM（Internet Download Manager）：下载引擎确实强，但**仅支持 Windows、界面陈旧、需付费**（约 25-75 美元买断），且浏览器扩展在浏览器更新后经常失灵。
4. 免费替代品的现状都不理想（详见竞品分析）：
   - Motrix：项目实质停滞，Electron 架构内存占用约 125-130MB，用户反馈"每次重开应用像重新开始"（任务历史保留差）；
   - Free Download Manager：官网在 2020-2022 年间曾分发恶意软件（Linux 版下载链被劫持），历史信任污点；部分版本带广告；
   - Gopeed：浏览器扩展不可靠（弹窗被压底、拦截无响应），多任务时内存达 300-700MB，Windows 上有杀毒软件误报；
   - Neat Download Manager：仅 600KB 非常轻量，但仅英文、功能简陋、无 Linux 版、界面老旧；
   - aria2 + AriaNg：引擎强大但需要写配置文件、命令行操作，对普通用户门槛过高。

**现在怎么解决的**：忍受浏览器慢速下载 / 付费买 IDM / 用迅雷并忍受广告 / 折腾 aria2。

**为什么不行**：每个方案都在"速度、免费、现代、轻量、可信赖"这五个维度里至少牺牲两个。市场上没有一个产品同时满足：**开源免费 + 界面现代 + 轻量（非 Electron）+ 断点续传可靠 + Windows 优先且后续支持 macOS**。

## 3. 目标用户画像

### 主要画像 P1：「数字搬运工」型重度下载用户
- **年龄/职业**：25-40 岁，开发者、设计师、视频创作者、科研人员、学生（毕业论文季下载文献与数据集）。
- **场景**：每周多次下载 1-50GB 的大文件——GitHub Release、系统 ISO、AI 模型权重（HuggingFace 类）、软件安装包、视频素材。
- **技术水平**：中高级。会看 GitHub、讨厌广告、了解开源，但不想为下载工具写配置文件。
- **现有工具与不满**：用过 IDM 嫌其贵且界面旧；用过 Motrix 担心其停止维护；用浏览器下载器被断点丢进度折磨过。
- **转投理由**：Rust 原生引擎 = 轻量且快；Tauri = 安装包小、内存占用远低于 Electron；开源 = 无广告无上传无后门；任务持久化 = 重启电脑也不丢进度。

### 次要画像 P2：普通大文件下载用户
- **年龄/职业**：任意，办公室职员、学生。
- **场景**：网络不稳定（家庭 Wi-Fi、公司网络限流），下载几个 GB 的文件经常中途失败。
- **技术水平**：初级。只会"复制链接、粘贴、点下载"。
- **转投理由**：界面现代易上手、暂停恢复一键完成、免费无广告。

### 反画像（不服务谁）
- 需要 BT/磁力/P2P 下载的重度用户（V2 之后再考虑，现阶段请用 qBittorrent）。
- 需要流媒体视频解析下载的用户（请用 Downie/yt-dlp 类工具）。
- 需要 FTP/SFTP/网盘协议的企业用户。

## 4. 竞品分析

### 4.1 直接竞品（5 个）

| 竞品 | 核心能力 | 优势 | 劣势（主要来自用户差评与社区反馈） | 定价 |
|------|----------|------|----------------------------------|------|
| **IDM**（Internet Download Manager） | 动态分片多线程、浏览器接管、视频嗅探、计划任务、队列 | 下载引擎业界标杆；断点续传极可靠；浏览器集成成熟（25 年积累） | 仅 Windows；界面陈旧（2026 年仍未重设计）；付费买断且试用期满后弹窗骚扰；浏览器更新后扩展经常失灵需手动修复；盗版/破解安装包泛滥带来安全风险 | 约 $24.95 起买断（区域/渠道有浮动），30 天试用 |
| **Motrix** | 基于 aria2，HTTP/FTP/BT/磁力，界面现代，浏览器扩展 | 界面公认"清爽优雅"；开源（56K+ star）；跨平台；免费无广告 | 项目实质停滞（核心开发者回归生活）；Electron 内存约 125-130MB；BT 控制粒度弱；**用户差评：不保留下载历史，重开应用"像重新开始"**；内置定制版 aria2 缺维护，对现代 TLS/反爬环境无力 | 免费（开源） |
| **Free Download Manager（FDM）** | 多线程分段、BT 内置、浏览器集成、跨平台、Android 版 | 免费多协议；断点自动续传；多语言；1.8 亿装机量 | **官网 2020-2022 年分发过被劫持的 Linux 恶意安装包（卡巴斯基披露）**，信任污点长期存在；低配机器上 CPU/内存占用高；Brave 等非主流浏览器接管失效（用户原话："It doesn't catch from my Brave browser. Bug?"）；插件系统存在安全风险；部分版本/地区有广告与捆绑 | 免费（闭源，客户端名义开源） |
| **Gopeed** | Go+Flutter，HTTP/BT/磁力/ed2k，REST API、Webhook、扩展系统 | 真正全平台（含移动端与 Docker）；开源无广告；更新活跃（2026 年仍在发版）；对开发者友好 | 浏览器扩展不可靠（弹窗被压到最底层、拦截后无响应，Issue #1160/#1376）；资源占用与"轻量"宣传不符（4-5 任务内存 300-700MB，闲置 CPU 可飙 30%）；Windows 杀毒误报 host.exe/updater.exe；不支持 FTP/SFTP/Metalink；扩展系统仅 ES5.1 | 免费（GPLv3） |
| **Neat Download Manager（NDM）** | 32 线程分段下载，浏览器扩展 | 极轻量（约 600KB）；免费；实测速度可比 IDM；Win/Mac 双平台 | 无官方中文；功能极简（无队列/计划/分类管理）；无 Linux 版；界面老旧；社区与文档薄弱 | 免费（闭源） |

### 4.2 替代方案（3 个）

| 替代方案 | 定位 | 用户为何最终不满意 |
|----------|------|--------------------|
| **浏览器内置下载器**（Chrome/Edge 默认） | 零门槛默认选项 | 单连接慢；浏览器崩溃/断网后进度丢失；无队列、无限速、无托盘常驻 |
| **aria2 + AriaNg**（或 Persepolis 等 GUI 封装） | 极客自建方案 | 需手写配置文件、命令行启动，"对普通用户门槛过高"；AriaNg 为网页界面，与系统集成松散；无托盘常驻的一体化体验 |
| **Downie（macOS）** | Mac 视频下载专精（1000+ 站点） | 付费（约 $19.99+）；仅 macOS；本质是视频解析工具，通用大文件直链下载只是附带能力；Windows 用户完全无法使用 |

### 4.3 新兴同类项目（验证技术方向，非成熟竞品）

| 项目 | 技术栈 | 状态 | 对我们的启示 |
|------|--------|------|--------------|
| Ferrix | Rust + Tauri + SQLite | 个人项目，2025 年，未签名分发，早期 Beta | 证明 Rust+Tauri 做下载器的路线可行；其"数据库持久化进度 + 指数退避重试"设计值得参考；未签名导致 SmartScreen/Gatekeeper 拦截是其最大分发障碍——**我们必须预留代码签名预算** |
| WDM | Tauri + React + yt-dlp | 业余项目，v0.0.2 | 同上；说明该赛道尚无"认真打磨"的成品，**市场空白真实存在** |

### 4.4 市场空白点结论（差异化机会）

1. **"现代 UI + 轻量"至今互斥**：界面现代的（Motrix/Gopeed）都背着 Electron/Flutter 的内存包袱；轻量的（NDM/aria2）界面都停留在上个时代。Tauri + Vue 3 是当前唯一能同时给出"现代界面 + 原生级资源占用"的组合。
2. **开源免费阵营集体"欠维护"或"欠信任"**：Motrix 停滞、FDM 有安全污点、Gopeed 扩展不可靠。用户在评论区反复表达"想要一个靠谱的开源下载器"。
3. **任务持久化是被低估的刚需**：Motrix 最刺眼的差评就是"不保留下载历史"。重启不丢任务应作为 P0 级卖点，而不是附加功能。
4. **Windows 优先 + 后续 macOS** 恰好卡在 IDM（Windows 独占）和 Downie（Mac 独占）之间的跨平台空档。

## 5. 我们的差异化定位

> **用户为什么放弃 IDM/FDM/Motrix，选 wtf-downloader？**

| 维度 | wtf-downloader 承诺 |
|------|---------------------|
| 速度 | 纯 Rust 下载引擎（独立 crate），多分片并行，性能对标 IDM/NDM |
| 轻量 | 非 Electron 架构，目标：安装包 < 15MB，常驻内存 < 80MB（待架构师与性能测试确认） |
| 可靠 | 任务状态持久化到本地数据库，应用崩溃/断电/重启后进度无损恢复 |
| 界面 | 现代桌面应用质感，免费开源，无广告、无弹窗、无上传 |
| 边界克制 | MVP 专注 HTTP/HTTPS 直链下载一件事，不碰 BT/视频解析，避免重蹈"全协议 = 全都做不好"的覆辙 |
| 跨平台路径 | Windows 优先打磨，macOS 复用同一引擎 crate 平滑跟进 |

## 7. MVP 范围（锁定，不得扩大）

以下范围来自用户确认的核心需求，为 Phase 1-3 交付边界，任何扩大都需回到主理人重新确认：

1. **HTTP/HTTPS 直链多分片下载**：Range 探测、分片并行、单连接降级。
2. **断点续传**：分片级进度记录，续传从分片已完成位置继续。
3. **限速**：全局 + 单任务，即时生效。
4. **任务持久化与重启恢复**：本地持久化，重启后自动恢复任务列表与进度。
5. **系统托盘常驻**：关窗驻留、托盘快捷操作、退出。
6. **任务管理**：添加/暂停/恢复/重试/删除、实时状态与速度展示。
7. **基础设置**：下载目录、分片数、限速默认值、开机自启。
8. **失败自动重试**（最小集：固定次数 + 简单退避）。
9. **架构约束**：前端 Vue 3 + TypeScript；下载引擎为独立纯 Rust crate（不依赖 Tauri 运行时，可独立编译测试）；客户端壳为 Tauri。

## 8. 明确不做清单（Out-of-Scope，每条带原因）

| # | 不做的事 | 原因 |
|---|----------|------|
| O1 | BT / 磁力链接 / ed2k 等 P2P 协议 | 用户明确划入 V2；P2P 引擎复杂度高（DHT/Tracker/做种），会拖垮 MVP 交付，且 qBittorrent 已是该领域成熟方案 |
| O2 | 视频站点解析（yt-dlp 类能力） | 用户明确划入 V2；解析规则维护成本极高（站点频繁改版），与下载引擎核心竞争力无关 |
| O3 | FTP / SFTP 协议 | 与 HTTP 分片引擎技术栈差异大，目标用户场景低频，V2 视需求评估 |
| O4 | 浏览器扩展接管 | MVP 以"粘贴 URL 添加任务"为最短路径；扩展涉及各浏览器商店审核与兼容维护，V2 统一规划（竞品差评重灾区，要做就要做好，不仓促上） |
| O5 | 订阅 / 付费 / 账号体系 | 开源免费是核心差异化定位；引入付费破坏与 IDM/迅雷对比时的信任优势 |
| O6 | 远程管理 / Web UI / REST API | 单机桌面工具是 MVP 定位；远程场景属于 V2 的引擎 crate 复用方向 |
| O7 | macOS 之外的 Linux/移动端 | 用户明确 Windows 优先、macOS 后续；其余平台无需求输入 |
| O8 | 下载队列 / 计划任务 / 分类管理 | 有价值但非核心，进 Backlog，避免 MVP 功能蔓延 |
| O9 | 多语言（i18n） | MVP 面向简体中文用户；文案结构上预留 i18n 接口即可（见非功能需求） |
| O10 | 杀毒白名单申诉之外的推广运营 | MVP 验证产品假设优先，推广属 Phase 4+ |

## 9. 验收标准（EARS 格式）

覆盖：添加任务 / 分片下载 / 断点续传 / 暂停恢复 / 重启恢复 / 限速 / 删除任务。EARS 句式：When/While/Where + 触发/状态，the system shall + 响应。

### 9.1 添加任务

- **When** 用户粘贴一个合法的 HTTP/HTTPS 直链并确认添加，the system shall 在 2 秒内完成文件名与文件大小探测（发起 HEAD/Range 探测请求），并在任务列表中创建状态为"等待下载"的任务。
- **When** 用户在确认添加前修改保存目录与文件名，the system shall 以修改后的值为准创建任务。
- **When** 用户粘贴的 URL 非法（格式错误、非 HTTP/HTTPS 协议、无法解析主机），the system shall 拒绝创建任务并给出明确错误原因，不产生任何半成品任务记录。
- **When** 用户提交的 URL 指向的服务器不可达或返回 4xx/5xx，the system shall 将任务置为"失败"态并展示具体 HTTP 状态码，用户可手动重试。
- **When** 用户粘贴的 URL 与剪贴板内容一致且应用处于空闲界面状态，the system shall 在添加入口预填该 URL（仅预填，不自动开始下载）。

### 9.2 分片下载

- **When** 任务开始下载且服务器响应表明支持 Range 请求（返回 206 或 Accept-Ranges 头），the system shall 按配置的分片数将文件切分为多个分片并行下载，各分片写入目标文件的对应偏移位置。
- **When** 服务器不支持 Range 请求，the system shall 降级为单连接下载整个文件，并在任务详情中如实展示"服务器不支持分段加速"。
- **When** 任务处于下载中状态，the system shall 以不低于 2 次/秒的频率向界面推送该任务的已下载字节数、总字节数、瞬时速度、预计剩余时间。
- **When** 某个分片请求失败且属可重试错误（超时、5xx、连接重置），the system shall 自动重试该分片（默认最多 3 次，指数退避），重试期间其余分片不受影响。
- **When** 所有分片下载完成，the system shall 将任务置为"已完成"，移除临时分片记录，目标文件大小与服务器声明的 Content-Length 一致（偏差时置为失败并提示校验不匹配）。

### 9.3 断点续传

- **When** 一个已暂停的任务被用户恢复且服务器支持 Range，the system shall 从每个分片已完成的字节位置继续下载，已下载进度不清零。
- **When** 下载因网络中断（Wi-Fi 切换、断网）而失败后网络恢复且任务配置了自动重试，the system shall 自动以断点位置续传，无需用户重新添加任务。
- **When** 续传请求返回 416（Range 不可满足）或服务器资源已变更（Content-Length/ETag 与持久化记录不一致），the system shall 终止续传，提示用户资源已变化并询问是否重新完整下载，不得静默把坏数据拼进文件。

### 9.4 暂停 / 恢复

- **When** 用户对一个下载中的任务点击"暂停"操作，the system shall 在 1 秒内停止该任务全部分片连接，持久化当前分片进度，任务转为"已暂停"态。
- **When** 用户对已暂停任务点击"恢复"操作，the system shall 按 9.3 的断点续传规则继续下载。
- **When** 用户通过托盘执行"暂停全部"，the system shall 同时暂停所有下载中任务，各任务进度均被持久化。
- **While** 任务处于已暂停状态，the system shall 不占用任何该任务的网络连接。

### 9.5 重启恢复

- **When** 应用被用户正常关闭（驻留托盘）或进程退出后再次启动，the system shall 在启动后 3 秒内从本地持久化存储加载全部任务记录，未完成任务以"已暂停"态呈现在列表中且进度完整。
- **When** 应用在下载中发生崩溃或被强制结束，the system shall 在下次启动时依据最近一次持久化的分片进度恢复任务（允许最多丢失崩溃前 1 个进度快照周期的数据）。
- **When** 应用启动时发现某任务的目标文件已被用户手动删除或移动，the system shall 将该任务置为失败态并提示"目标文件不存在，请重新添加"，不自动重建文件。
- **When** 持久化存储文件损坏，the system shall 尝试加载最近一次可用备份；全部不可用时以空任务列表启动并告知用户，不得循环崩溃。

### 9.6 限速

- **When** 用户设置全局速度上限为 X 且当前总下载速度超过 X，the system shall 在 2 秒内将所有任务的总下载速度收敛到 X 的正负 10% 以内。
- **When** 用户为单个任务设置速度上限 Y，the system shall 仅约束该任务，其他任务不受影响。
- **When** 用户在下载进行中修改限速值，the system shall 即时生效，无需暂停或重启任务。
- **When** 用户未设置任何限速，the system shall 不做主动限流，交由系统网络栈自然调度。

### 9.7 删除任务

- **When** 用户删除一个未完成的任务并选择"同时删除文件"，the system shall 移除任务记录、持久化数据及磁盘上的未完成文件（含分片临时数据）。
- **When** 用户删除一个未完成的任务但选择"保留文件"，the system shall 仅移除任务记录，未完成文件保留在原位置。
- **When** 用户删除一个已完成的任务，the system shall 仅移除任务记录，已完成的文件始终不被删除。
- **When** 用户删除一个下载中的任务，the system shall 先停止该任务全部网络连接再执行删除，删除过程不阻塞其他任务。
- **When** 用户执行任何删除操作，the system shall 弹出确认提示，明确告知是否会影响磁盘文件。

## 10. 边界条件

| 类别 | 边界场景 | 期望行为 |
|------|----------|----------|
| 空状态 | 无任何任务时的任务列表 | 展示引导文案（说明"复制链接后点击添加按钮即可开始下载"）与添加任务入口，不展示空白区域 |
| 错误状态 | URL 无法解析 / DNS 失败 / TLS 证书错误 / 403 / 404 / 5xx | 任务置失败，错误信息含具体原因（区分网络错误与服务器拒绝），可手动重试 |
| 错误状态 | 磁盘写入失败（目录不存在、无写权限、磁盘满） | 任务置失败并明确提示原因；下载开始前与过程中都做磁盘剩余空间检查（剩余空间 < 待下载大小 + 缓冲时提前告警拒绝开始） |
| 加载状态 | 应用启动加载持久化任务期间 | 提供加载中反馈，超过 3 秒仍未完成时提示任务库较大（属异常，需排查） |
| 边界值 | 0 字节文件 / 未知大小的流式响应（无 Content-Length） | 0 字节文件直接标记完成；无 Content-Length 时降级单连接流式下载，进度按字节累计展示、不展示百分比 |
| 边界值 | 超大文件（> 100GB） / 分片数与文件大小的关系（文件小于分片数 x 最小分片尺寸时自动减少分片数） | 分片策略自适应，不为小文件开多连接 |
| 边界值 | 文件名含非法字符 / 与目录中已有文件重名 | 按操作系统规则净化文件名；重名时默认自动追加序号（如 filename (1).zip），用户在添加确认环节可改 |
| 并发 | 用户同时添加大量任务 / 多任务同时高速下载 | 默认最大并行下载任务数（建议 3-5，可配置），其余任务排队等待；UI 不因任务数多而失去响应 |
| 并发 | 用户在下载中对同一任务快速连续点击暂停/恢复 | 操作串行化处理，最终状态与用户最后一次操作一致，不产生僵尸连接 |
| 离线 | 下载中系统断网 | 全部下载中任务转失败/重试流程，网络恢复后按自动重试策略续传；不崩溃、不白屏 |
| 权限拒绝 | 保存目录无写权限 / 杀毒软件锁定临时文件 | 明确报错提示，引导用户更换目录或检查杀毒软件设置 |
| 重定向 | URL 返回 30x 重定向链（含跨协议 HTTP 到 HTTPS 跳转） | 自动跟随（默认上限 10 跳），最终 URL 与初始记录不一致时以最终 URL 为准并支持基于最终 URL 的续传校验 |
| 认证资源 | URL 需要请求头/Cookie 才能下载 | MVP 仅支持在添加任务时手动附加自定义请求头（最小实现）；不做站点级自动登录 |

| 安全-传输 | 支持现代 TLS（跟随 rustls/OpenSSL 选型，架构师确认），对证书错误默认拒绝并明示 | P0 |
| 兼容性 | Windows 10 21H2 / Windows 11 最新两个大版本；WebView2 运行时（Tauri 依赖，安装包需处理缺失场景）；macOS 在 V2 阶段定义为最近两个大版本 | P0 |
| 可访问性 | 键盘可完成全部核心操作（添加/暂停/恢复/删除任务）；文字对比度满足 WCAG 2.1 AA | P2 |
| 国际化 | 界面文案集中于统一资源文件，预留 i18n 接口；MVP 仅交付简体中文 | P2 |

| 文案约束 | 界面与文档禁止出现空洞占位文案（如"Welcome to""Lorem ipsum"），所有文案面向真实场景撰写 | P0（规范约束） |

## 12. 数据埋点方案（本地统计，隐私优先）

本产品为桌面工具且以"无追踪"为卖点，**不做任何云端埋点**。改为本地匿名统计，用于验证产品假设，用户可在设置中查看与清除：

| 事件类别 | 必埋事件（本地） | 验证的假设 |
|----------|------------------|------------|
| 激活 | first_task_created | 用户完成第一个核心动作（添加首个任务）的转化 |
| 使用 | task_added / task_completed / task_failed / task_resumed_after_pause / task_recovered_after_restart | 核心流程健康度；**重启恢复使用率是本产品核心卖点的直接验证指标** |
| 引擎 | segment_degraded_to_single（降级单连接次数）/ retry_exhausted（重试耗尽次数）/ speed_limit_changed | 服务器 Range 支持率、引擎可靠性、限速功能使用率 |
| 留存 | app_launch / app_session_duration（本地记录） | 使用频次与常驻价值 |
| 异常 | engine_panic / persistence_load_failed / disk_write_failed | 稳定性监控依据（本地日志 + 计数） |

实现要求：
- 封装统一 `track_event(name, props)` 本地接口，事件命名 `{对象}_{动作}`，属性附带时间戳与应用版本（不含任何可识别用户身份的信息）。
- 全部数据仅存本地；不采集 IP、不上报 URL 内容、不存原始输入内容。
- 设置页提供"清除本地统计"入口。

| # | 风险 | 影响 | 概率 | 缓解措施 |
|---|------|------|------|----------|

| R4 | 断点续传与资源变更（服务器端文件更新导致续传拼接坏文件） | 高 | 中 | 持久化 Content-Length/ETag/Last-Modified，续传前校验，不一致强制重下（验收标准 9.3 已覆盖） |
| R5 | 持久化写入频率 vs 磁盘磨损/性能的平衡没做好，HDD 机器体验差 | 中 | 中 | 快照周期可配置；写入策略（全量快照 vs 增量日志）由架构师专项设计 |
| R6 | Tauri 系统托盘在不同 Windows 版本上的兼容性问题（托盘是 P0 功能） | 高 | 低 | MVP 测试矩阵覆盖 Win10 21H2 + Win11；托盘降级方案：托盘不可用时保持常规窗口最小化运行 |
| R7 | macOS 支持承诺延期，跨平台卖点落空 | 中 | 中 | 引擎为独立纯 Rust crate，天然跨平台；macOS 排期在 V2 计划中明确里程碑；宣传口径 MVP 期只承诺 Windows |
| R8 | "不做 BT/视频解析"导致部分早期用户流失到 Gopeed/qBittorrent | 低 | 高 | 接受该取舍——MVP 聚焦是用户明确决策；在产品说明中明确 roadmap 管理预期 |
| R9 | 竞品（尤其活跃的 Gopeed）快速补齐"轻量+现代"短板 | 中 | 低 | 差异化重心放在引擎可靠性（Rust 内存安全 + 持久化设计）与任务持久化体验，不与他人拼功能数量 |
| R10 | 性能目标（内存 < 80MB 等）在 Tauri + WebView2 架构下无法达成 | 中 | 低 | 将资源占用指标写入架构师技术方案的验收标准，Phase 2 早期做性能基准，超标及时调优或调整目标并同步主理人 |
