# wtf-downloader UI/UX 设计方向（Phase 1）

> 产出人：设计师 颜好看 | 日期：2026-10 | 状态：设计方向（待 Spec 锁定）| **版本：v4**
> **变更记录 v4（2026-10-23）**：用户指定品牌色变更——**Cyan → 黑灰中性 / PrimeVue 风**。primary 重新定义为"最高对比度中性色"（非色相）：浅色主题主按钮近黑 `#111417` + 白字，深色主题反转为主按钮近白 `#F5F6F8` + 深字；语义色仅小面积徽章；数据可视化灰阶透明度阶梯；下载中进度条改 primary 黑白反差表达。v3 竞品分析与信息架构结论不变。
> 产品寄存器：**Product（产品型）**——设计服务产品，标杆是"赢得熟悉感"，克制用色 + 黑灰中性 primary（v4）
> 三轴刻度：DESIGN_VARIANCE **3**（工具类，可预测对称） / MOTION_INTENSITY **3**（功能性动效，150ms 收敛） / VISUAL_DENSITY **6**（任务列表为数据密集区）

## 1. 竞品 UI 分析（5 款）

### 1.1 Internet Download Manager（IDM）
- **优势**：多线程引擎口碑极强；下载分类树（压缩包/视频/程序）习惯深入人心；进度信息（速度/剩余时间/分块视图）完整。
- **劣势**：UI 被普遍评价为"Windows 98 味"，多年未翻新；无深色模式；付费 + 更新弹窗骚扰感强；仅 Windows。
- **启示**：信息完整度是下载器的底线；但视觉过时会让"现代界面"成为我们的核心差异化卖点。

### 1.2 Free Download Manager（FDM）
- **优势**：现代度尚可，功能全（BT/直链/计划任务），跨平台。
- **劣势**：设置项直接暴露在 UI，密度高、新手困惑；安装包约 40MB、资源占用偏高；各平台成熟度不均；历史上有推广组件，信任感打折。
- **启示**：**高级选项必须渐进披露**（折叠/弹窗内），不能像 FDM 一样把所有开关摊在主界面。

### 1.3 Motrix（v1 / v2 beta）
- **优势**：公认"最好看的开源下载器"——清爽、无广告、无会员套路，深色模式完整；任务列表"进度/速度/状态一个视图"的信息聚合是品类最佳实践；v2 用 Tailwind + shadcn/ui 重写，进一步向 Linear 系审美靠拢。
- **劣势**：Electron 打包重（我们是 Tauri，天然优势）；v2 仍 beta；仪表盘对多数用户是"从不看的一屏"。
- **启示**：MVP **不做仪表盘**，打开即任务列表；深色完整度（列表、弹窗、托盘、通知全链路深色）是"现代感"的重要来源。

### 1.4 AriaNg（aria2 WebUI）
- **优势**：表格化任务列表信息密度高，实时统计与多 RPC 管理专业；响应式。
- **劣势**：运维向审美，面向"管 aria2 的人"而非普通用户；aria2 的配置复杂度直接暴露给用户；纯 Web 前端，无原生托盘/通知体验。
- **启示**：表格密度值得学，但要用"卡片行 + hairline 分隔"的现代化手法重做，避免表格线框审美；技术复杂度（分片数、连接数）不应出现在默认路径上。

### 1.5 AB Download Manager / Neat Download Manager
- **AB 优势**：dark-first 现代 UI，任务条目展示速度/大小/百分比/剩余时间清晰，有队列与调度；**AB 劣势**：Qt 自绘控件质感不及 Web 技术栈，包体大。
- **Neat 优势**：极轻量、悬浮抓取视频好用；**劣势**：UI "Basic"，功能单薄。
- **启示**：AB 的"任务条目信息结构"是我们任务行的直接参照；Tauri + Vue 3 可以做出比 Qt 更精致的密度与动效。

**竞品结论**：品类里"引擎都不差，输赢在界面"。IDM 输在过时、FDM 输在杂、AriaNg 输在运维味、Neat 输在简陋、Motrix 赢在克制但输在 Electron。我们的机会点：**Motrix 级的克制审美 + Tauri 原生轻量 + Windows 11 Fluent 原生质感（圆角/贴边/主题跟随）**。

## 2. 2025-2026 桌面工具设计趋势与对标品牌

### 2.1 趋势要点（调研摘要）
1. **Linear 系统而非 Linear 皮肤**：近黑非纯黑背景（约 `#0F1011` 层级）、亮度递进代替阴影、hairline 边框（约 `#23252A`）、单一品牌色每屏 ≤2 处。2026 年照抄 Linear 紫渐变已被识别为"AI 生成味"，但**底层系统**（Token 化、密度、键盘优先）仍是工艺标杆。
2. **Calm UI**：减法设计——每个元素都要回答"是否帮助用户完成任务"；通知默认沉默；动效只在传达含义时存在。
3. **键盘优先/命令化**：Raycast/Superhuman 证明桌面工具用户重视快捷键；快捷键提示应内联展示而非教程。
4. **精细玻璃拟态**（仅限 chrome 层：标题栏/弹窗边框），内容层禁用；对比度守卫 4.5:1。
5. **等宽数字**：数据密集 UI 中速度/大小/时间用 tabular-nums，防止刷新时跳动。

### 2.2 锁定对标品牌（3 个）
| 对标 | 借什么 | 不借什么 |
|------|--------|----------|
| **Motrix**（品类直接对标） | 任务列表信息聚合结构、克制的功能布局、无广告的纯净感 | Electron 审美惯性、v2 的仪表盘 |
| **Linear**（工艺标杆） | 四层亮度递进表面、hairline 边框、Token 纪律、150ms 动效收敛 | Linear 的紫色/紫渐变品牌色（换为我们自己的黑灰中性 primary——PrimeVue 式"最高对比度中性色"，v4） |
| **Raycast**（交互标杆） | 键盘可达、单输入框渐进披露、内联快捷键提示 | 命令面板全量生态（MVP 仅 Ctrl+N / Ctrl+F / Ctrl+K 预留） |

## 3. 配色基调（Token 表，浅/深双主题）【v4】

**策略**：中性色 90% + **黑灰中性 primary**（v4 起，参照 PrimeVue 官网风格）+ 语义色仅小面积徽章。**默认深色主题**（下载器长时间挂机场景），跟随系统 `prefers-color-scheme`。

> **v4 变更（用户指定，2026-10-23）**：品牌强调色由青蓝 Cyan 改为「黑灰中性」。primary 的定义是**"最高对比度中性色"而非色相**：浅色主题下主按钮/激活态为近黑 `#111417` 填充 + 白字；深色主题反转为近白 `#F5F6F8` 填充 + 深字。原"避开 AI 模板默认靛蓝 `#6366F1` 与紫粉渐变红线"的论证继续成立且更进一步——**全案无彩色品牌色**：语义色（绿/红/黄）仅用于小面积状态徽章；数据可视化用单一灰阶透明度阶梯表达（参照 PrimeVue 灰色柱状图三层透明度叠法，见 `--chart-1/2/3`）；图标激活/选中态用"primary 底色圆角块 + primary-fg 图标"手法；下载中进度条用 primary 黑白反差表达。

### 3.2 状态色语义（任务列表专用，v4）
| 任务状态 | 进度条/标识 | 说明 |
|---|---|---|
| 下载中 | `--primary-bg`（浅色主题近黑填充、深色主题近白填充，黑白反差表达"进行中"） | v4：不再使用彩色 accent |
| 已暂停 | `--muted`（进度条降透明度 60%） | 中性降透明，不抢注意力 |
| 已完成 | `--success`（仅对勾图标 + 细进度条满色，不做大面积绿） | 克制表达，语义色小面积 |
| 失败 | `--danger` + `--danger-soft` 底色 badge | 附错误原因与重试按钮 |
| 等待中 | `--meta`（条纹/斜纹轨道） | 队列语义 |

### 3.3 primary 使用纪律（v4）
primary 是"最高对比度中性色"，不是品牌色相。每屏 `--primary-bg` 实心填充 ≤2 处：主界面 = 「新建任务按钮 + 进行中任务的进度条」；弹窗 = 「主按钮」（focus ring 为半透明中性，不计入实心）。图标激活态/选中态统一用**"primary 底色圆角块 + `--primary-fg` 图标"**手法（参照 PrimeVue 侧栏选中块），禁止再用彩色标记激活。语义色（success/warn/danger）仅出现在小面积状态徽章与图标，禁止大面积填充；数据可视化（如未来统计）一律使用 `--chart-1/2/3` 灰阶透明度阶梯，不引入彩色系列。

## 4. 字体方案（含中文）

```css
--font-display: "Inter", "Noto Sans SC", "Microsoft YaHei UI", system-ui, sans-serif;
--font-body:    "Inter", "Noto Sans SC", "Microsoft YaHei UI", system-ui, sans-serif;
--font-mono:    "JetBrains Mono", "Cascadia Mono", Consolas, monospace;
```

- **Inter**（UI 拉丁/数字）+ **Noto Sans SC**（中文）：工具类产品标准配对，Windows 优先回退 Microsoft YaHei UI 保证无网络环境可用；离线 woff2 子集内嵌方案已获架构师批准（见 §9.1），字重收敛为 **400/500**；Noto Sans SC 按 unicode-range 拆 GB 常用区 + 拉丁区子集，总体积 ≤3MB。
- **JetBrains Mono** 专用于：下载速度、文件大小、剩余时间、URL——所有实时刷新数字用 `font-variant-numeric: tabular-nums`，防跳动。
- 字号层级（工具类收敛为 7 级）：12 / 13 / 14 / 16 / 18 / 20 / 24px。文件名 14px/500、元数据行 12px/400、窗口标题 16px/500、总速度 chip 14px mono。
- 字重两级（依 §9.1 字体硬约束收敛）：400 正文 / 500 小标题、按钮与标题（原 600 级取消，标题层级改由字号 + 字距表达）。ALL CAPS 标签（如筛选 TAB "DOWNLOADING"）加 `letter-spacing: 0.06em`；中文标签不强制大写。

## 5. 圆角 / 间距 / 阴影方向

- **圆角**（对齐 Windows 11 Fluent）：按钮与输入框 `--radius-md: 8px`；卡片/弹窗 `--radius-lg: 12px`；badge/速度 chip `--radius-sm: 6px`；圆形图标按钮 `9999px`。禁 ≥24px 过度圆角。
- **间距**：4px 网格（4/8/12/16/24/32）。列表行内边距 12px 16px；行高 64px（单行任务）与 84px（含进度条的主行）；弹窗内边距 24px。
- **阴影**：深色主题**不用投影表达层级**，靠亮度递进（`--bg → --surface → --surface-2`）；仅弹窗/下拉用 `--elev-raised` 一级投影。浅色主题允许 `0 1px 2px` 微投影。禁止"1px 边框 + 大模糊阴影"的幽灵卡片。
- **边框**：hairline 1px `--border`，行分隔用 `--border-soft`。禁止彩色侧条纹边框。

## 6. 图标库锁定（一套，不混用）

**锁定：Lucide（`@lucide/vue`，官方 Vue 3 包，v1.x / Lucide v1.61.0 版本线；详见架构文档 ADR-005）**

> 注：旧包名 `lucide-vue-next` 已于 2026-03 被 Lucide 官方废弃（deprecated），**禁用废弃包 `lucide-vue-next`**；依赖清单与设计引用一律使用 `@lucide/vue`，**全项目不得混用第二套图标库**（Tabler/Phosphor 等均禁用）。

理由：
1. **官方 Vue 3 支持**：`@lucide/vue` 为一等公民 SFC 导出，TypeScript 完整、tree-shaking 按需打包，契合 Tauri 小包体目标；
2. **统一描边语言**：24px 网格 / 2px 圆头描边 / 1500+ 图标，语义覆盖下载器全部需求（`download` `pause` `play` `trash-2` `link` `folder` `search` `settings` `moon` `sun` `x` `check` `rotate-cw` `alert-circle` `minus` `plus` `gauge` `list-filter` `keyboard` `menu`）；
3. **ISC 许可**（MIT 兼容），商用零风险；`currentColor` 继承文字色，深浅主题零额外配置；
4. 社区活跃、锁版本后无断更风险（Feather 官方停更，Lucide 是其社区延续）。

使用规范：尺寸 16px（行内）/ 20px（按钮内）/ 24px（独立）；描边统一 2px；`aria-hidden` 于装饰图标，语义图标配 `aria-label`。**全项目禁 emoji 图标**。

## 7. 核心页面设计要点（信息架构 + 交互，不做视觉稿）

### 7.1 主界面 = 任务列表（打开即达，无仪表盘）

**布局**：原生系统标题栏（依 §9.1 确认，MVP 不自定义）→ 顶栏 → 任务列表主体 → 底部状态栏。无侧边栏（MVP 单一列表，避免为导航而导航）。

**顶栏**（从左到右）：
- App 名（16px/600）；
- 筛选分段控件（Segmented）：全部 / 下载中 / 已完成 / 失败，右侧带数量 badge（12px）；**（2026-11-06 第七轮裁决已更新为「下载中 / 全部 / 已完成 / 失败」且默认进入下载中视图，以 Phase 2 DESIGN.md §2.2 为准；此行保留 Phase 1 原始方向记录）**；
- 搜索框（Ctrl+F 聚焦，按文件名过滤）；
- **新建任务按钮**（唯一 primary 填充按钮：浅色主题近黑底白字、深色主题近白底深字，v4；Lucide `plus` 16px + "新建任务"，快捷键提示 Ctrl+N 悬停显示）；
- 右侧总速度 chip（mono 字体，如 `↓ 12.4 MB/s`，全局限速开关入口）。

**任务行信息层级**（自上而下三层）：
1. 第一层：文件名（14px/500，超长省略号 + 悬停 tooltip 全名）+ 右侧操作组（**hover 才显示**：暂停/恢复 `pause`/`play`、更多 `menu` 内含打开文件/打开目录/删除）；
2. 第二层：进度条（4px 高、全宽、圆头）+ 右端百分比（mono 12px）；
3. 第三层：元数据行（12px，`·` 分隔）：已下载/总大小 · 速度（下载中才显示，mono，中性 `--fg-2` 色，v4 不再用彩色 accent）· 剩余时间（mono）· 分片数（如 `16/32`，高级用户向，muted 色）。

**交互**：行 hover 背景 `--surface-2`（150ms）；点击行选中（`--primary-soft` 背景），Space 暂停/恢复、Del 删除（二次确认或可撤销 toast）；删除已完成的直接移除 + toast "已移除 [撤销]"；批量操作 MVP 从简。

**状态覆盖（5 态）**：
- Empty：居中 Lucide `download` 24px + "还没有下载任务" + 副文案"按 Ctrl+N 或点击右上角新建任务，粘贴链接即可开始"；
- Loading：首屏骨架行（3 行 shimmer，200ms 循环）；
- Error：行内 `alert-circle` + 错误 badge（danger-soft 底）+ 展开可见错误原因 + "重试"按钮；
- Populated：如上；
- Edge：超长文件名省略、0 字节/未知大小显示 `--`、上千任务虚拟滚动（预留）。

### 7.2 添加任务弹窗（渐进披露，单主路径）

- 触发：Ctrl+N / 顶栏按钮 / 托盘菜单 / 未来浏览器扩展推链接。
- **默认只露一个输入**：URL 多行输入框（自动焦点、支持粘贴多条 URL 批量识别、mono 字体、粘贴即校验 `http(s)://` 格式并给出内联错误"链接格式不正确"）；
- URL 校验通过后**自动解析并显示**：文件名（可编辑）+ 文件大小（服务端支持时）+ 保存路径（默认下载目录，`folder` 图标点开系统目录选择器）；
- **高级选项折叠区**（默认收起，`chevron-down`）："下载分片数"（默认 16，滑块 1–64，附 helper text"分片越多对服务器压力越大"）；
- 底部：左"取消"（ghost）、右"开始下载"（primary 主按钮，v4 黑白反差，Enter 提交）+ 单条 URL 时显示预计并发提示。弹窗宽 480px、`--radius-lg`、`--elev-raised`、深浅主题随系统。
- 提交后弹窗即关、任务入列表并自动开始，Toast "已添加 N 个任务"。

### 7.3 系统托盘

- 托盘图标（深浅主题自适应单色图标）；tooltip 为**低频辅助通道**：1Hz 刷新、仅活动任务时更新，文案如"wtf-downloader — 3 个任务下载中 1.2 MB/s"（Windows 经 `TrayIcon::set_tooltip` 支持运行时更新；Linux 无 tooltip）；**总速度主展示位在应用内任务页与托盘菜单项文本**（无平台限制）；
- 左键单击：显示/隐藏主窗口；
- 右键菜单（原生菜单，随系统主题）：`显示/隐藏主窗口` / `暂停全部` / `恢复全部` / `全局限速：关|5MB/s|10MB/s（复选组）` / `退出`；
- 关闭窗口 = 最小化到托盘（下载器惯例，设置项可改为直接退出）；下载完成发系统通知（可关）。

### 7.4 主题与动效
- 深浅主题跟随系统：CSS 变量 + `prefers-color-scheme` 媒体查询双写，Tauri 监听系统主题变化实时切换；深色为默认展示（官网截图/README 用深色）。
- 动效全部 ≤300ms 且传达含义：进度条数值平滑插值（避免每秒跳变）、行进入 200ms fade+slide 8px、状态切换 150ms、完成瞬间进度条满格 + 对勾 200ms 缩放一次；`prefers-reduced-motion: reduce` 时全部退化为瞬切。

### 9.1 设计联动确认（已锁定，Phase 2 按此收敛）

1. **标题栏**：MVP 使用原生系统标题栏，不启用 Mica、不自定义标题栏（自定义需自实现拖拽/窗口按钮/Snap Layouts，属装饰性投入）。Token 预留路径：`--bg` 为不透明色，另预留 `--bg-translucent` 半透明叠加版本（深浅双主题各一值，Phase 2 落入 design-tokens.json 的 C-extension 层），后续启用 Mica 时无需重新设计。若启用，需按"mica → acrylic → 不透明"降级链处理 Win10。
2. **字体**：批准离线 woff2 子集内嵌（随包本地加载，无运行时下载）。硬约束（口径已按架构师 10.2 澄清修正）：**字重维度 5 个资源**（Inter 400/500、Noto Sans SC 400/500、JetBrains Mono 400）；Noto Sans SC 按 unicode-range 拆子集（GB 常用区 + 拉丁区），**子集拆分后的物理文件数不设上限，总体积 ≤3MB 不变**；CSS 保留系统字体回退栈（防加载失败白屏）。字重清单将体现在 design-tokens.json `font.weight` 节点（400/500 两级）——窗口标题改用 500 + 字号区分层级（不新增 600 字重文件）。对比度校验结论：窗口标题 16px/500 用 `--fg`（深色 #EDF0F4 / 浅色 #16181D）对 `--bg` 对比 ≈15:1，远超 4.5:1，无需补 letter-spacing；`--fg-2` 元素（如顶栏 App 名若用次级色）也有 ≈9:1 余量，字重降级无对比度风险。

### 9.2 primary 对比度验算（v4，WCAG 2.x 相对亮度法）

> 用户裁决要求：深色 primary 近白对 `--bg` ≥ 4.5:1、浅色 primary 近黑对 `--bg` ≥ 4.5:1。验算如下，全部通过且余量充足。

| 验算项 | 前景 | 背景 | 对比度 | 判定 |
|---|---|---|---|---|
| 浅色 primary 对 `--bg` | `--primary-bg` `#111417` | `--bg` `#F7F8FA` | **17.4:1** | 达标 ≥4.5:1 |
| 浅色 primary-fg 对 primary-bg（按钮文字） | `#FFFFFF` | `#111417` | **18.5:1**| 达标 |
| 深色 primary 对 `--bg` | `--primary-bg` `#F5F6F8` | `--bg` `#0B0D10` | **18.0:1** | 达标 ≥4.5:1 |
| 深色 primary-fg 对 primary-bg（按钮文字） | `#0B0D10` | `#F5F6F8` | **18.0:1**| 达标 |
| 浅色 primary 悬停态文字 | `#FFFFFF` | `--primary-hover` `#33373D` | **12.0:1**| 达标 |
| 深色 primary 悬停态文字 | `#0B0D10` | `--primary-hover` `#E2E5EA` | **15.4:1**| 达标 |
| `--fg`/`--bg` 基线（浅/深） | `#16181D` / `#EDF0F4` | `#F7F8FA` / `#0B0D10` | **16.7:1 / 17.0:1**| 达标 |
| `--muted`/`--bg`（深） | `#8B93A1` | `#0B0D10` | **6.3:1**| 达标 |

结论：v4 黑灰中性 primary 在深浅双主题下的按钮文字、hover 态、focus ring（半透明中性环叠加在实底上仍保 ≥4.5:1）均满足 WCAG AA（正文 ≥4.5:1），且无 v3 彩色 accent 的色相-明度耦合风险。深色主题中性四层递进（`#0B0D10 → #111419 → #191D23 → #21252C`）沿用近黑蓝调框架、色相收敛更偏中性，亮度递进表达层级的原则不变。
